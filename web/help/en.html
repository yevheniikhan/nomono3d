Help

nomono3d rebuilds a flat image as real 3D geometry from a depth map. A 360° panorama becomes a space you can look around and shift your viewpoint in, with digitised 3D objects standing on its real depth. An ordinary photo becomes a “window” with parallax: near things move against far ones as you tilt the phone, move the mouse or your head.

Quick start

  1. Choose 360° panorama or Photo at the top of the start screen. A picture that is not 2:1, 1:1 or 4:1 switches to Photo by itself.
  2. Pick an item in the Library, or load your own image into the first slot (tap, drag and drop, or paste from the clipboard).
  3. Add a depth map in the second slot, or leave it empty: when an AI engine is available (see below) the map is generated for you. Generate creates it right away so you can check or download it (Download).
  4. Press View in 3D.

The gyroscope and the camera work only over a secure connection: https:// or http://localhost. Opening the file by double-click (file://) will not work: a web server is required.

AI depth maps

The top-left corner of the start screen shows which engine is available:

EnginePanoramasPhotos
GPU server (the site is served by the nomono3d server, e.g. from Google Colab)DA360, a network trained for 360° images: up to 4096×2048Depth Anything V2: up to 2048 px
In the browser (any static hosting)—Depth Anything V2 Small on WebGPU or WASM. The first run downloads a ~50 MB model
  • When an image from the server library gets an AI depth map, the map is saved next to it (name_depth.png), so it opens instantly next time.
  • Save to library (next to the image size) saves your own image and its depth map into the server library.
  • Generated maps are relative: they know what is nearer and what is farther, not metres. For panoramas the app fits the scale to the ground automatically; for photos you set the depth by eye with the Depth slider.

To run the GPU server for free, open colab/nomono3d_colab.ipynb from the project repository in Google Colab: it prints a public link and a QR code for your phone.

JPEG, PNG, WebP or AVIF. Larger images are scaled down to the GPU limit automatically (4096 on low-end phones). If the eyes of a stereo panorama are swapped, tick swap eyes (editor → “Panorama and depth”) or set "swapEyes": true in manifest.json.

Photos

Any ratio, landscape or portrait, JPEG, PNG, WebP or AVIF. EXIF rotation is applied by the browser.

Depth map

  • A greyscale image of the same framing: 2:1 for a panorama (one eye; a 1:1 map of a stereo panorama also works), the photo's own ratio for a photo.
  • White = near, black = far (inverse depth, as neural networks produce it). If yours is the other way round, tick invert in the editor or set "depthInvert": true.
  • PNG is better than JPEG. 8-bit “terracing” is smoothed automatically while object edges stay sharp; blurred edges (typical for neural maps) are sharpened using the photo's colours.
  • Naming: the image name plus _depth (also -depth, .depth, _disp): forest.jpg + forest_depth.png.
  • For a stereo panorama without a map, open it once and save the estimated map: editor → “Panorama and depth” → ⇩ Depth map .png.

How parallax is built. The image is rendered as two layers. The front layer holds objects with exact outlines: they shift according to their own depth and are not stretched towards the background. The back layer is the background continued behind them, mirrored from the visible edge: it shows in the gaps that open when the viewpoint moves.

Depth views

The Depth button opens a small panel of overlays that show how the image was rebuilt. They help to judge a depth map and to place objects. Opacity blends each view with the photograph.

ViewWhat it shows
Depth (0–1)the depth map in grey, white is near
Colour (2)a colour scale from red (near) to blue (far)
Contours (3)lines of equal distance; in panoramas every metre, thicker every 5 m and 25 m
Slice (4)one distance band lit, the rest dimmed; Distance moves the band
Normals (5)the orientation of the rebuilt surfaces: floors, walls and slopes in different colours
Fog (6)aerial haze that grows with distance; Fog distance sets where it starts

The numbers are keyboard shortcuts. Download depth map saves the map as an 8-bit PNG.

Background (photos, on a nomono3d server such as the Colab notebook): what appears behind objects when the viewpoint moves. AI (MI-GAN) lets a neural network paint it (best in foliage, grass and other textures); Built-in mirrors the nearby background in the browser and needs no server. Switching rebuilds the photo; your 3D objects stay.

Measuring

Depth ▸ Measure distance (or M): tap two points on any surface. The label shows the straight distance and, in panoramas, the height difference (↕). Tap again for another measurement; Clear removes them all, Done or Esc stops measuring.

Panoramas are in metres from the calibrated scale (the camera height, about 1.6 m, or a fit of the floor). Photos have no absolute scale: their distances are relative to the nearest surface (1.00 × = the nearest point).

Photo mode

The photo is the window and the scene sits behind it. The frame stays still on screen, near objects drift against your movement and far ones with it.

How the site finds files

  1. nomono3d server (api/list): the library folder of the server, e.g. Google Drive in Colab.
  2. PHP (list.php): most ordinary hosting plans. Nothing to configure. Thumbnails are cached in .thumbs/ (needs GD or Imagick).
  3. manifest.json: hosting without PHP (GitHub Pages, Netlify, Cloudflare Pages). After adding files run python tools/build-manifest.py (thumbnails need pip install pillow) and upload the updated manifest.json files and thumbs/ folders.
  4. The server's folder listing (Apache/nginx autoindex, python -m http.server).
  5. GitHub Pages: if nothing else is available, the list is read from the repository through the GitHub API.

Deploying to your hosting

  1. Copy the content of the web/ folder into the site root via FTP or the hosting panel, keeping the folder structure.
  2. Enable HTTPS (a free Let's Encrypt certificate is in almost every hosting panel).
  3. Put panoramas into panoramas/, photos into photos/, models into models/, then open the site.
  4. If the hosting shows error 500, delete .htaccess (it is optional).

The demos in panoramas/Demo/ and photos/Demo/ are synthetic test scenes with exact geometry. Delete them together with models/demo-tree.glb when you no longer need them.

3D objects (panoramas and photos)

Model formats

  • GLB / GLTF (recommended): PBR materials, animations, Draco compression, KTX2 and WebP textures.
  • OBJ + MTL with textures: select all files together or zip them.
  • FBX (with animations), USDZ, 3MF, STL (millimetres are converted to metres).
  • PLY (mesh or point cloud), LAS (uncompressed point clouds; convert LAZ to LAS first), XYZ, PCD.
  • ZIP with any of these plus textures.

Gaussian splats (.splat, .spz, splat PLY) are not supported yet: export a mesh (GLB, OBJ) or a point cloud from your scanning app.

Adding

  • Cube button → + Model file, or drop files onto the panorama (desktop), or Library (models from models/).
  • The object lands on the surface at the centre of the view. If that is a wall or a trunk, it stands on the ground in front of it.
  • Photos work the same way, but their space is relative (the nearest surface is at distance 1), so sizes are set by eye.
  • Size is real when the model is in metres; millimetres and centimetres are detected automatically. Set the exact height in Height, m.

Scene lighting. Objects are lit by the panorama itself (light from the sky and surroundings). ☀ Sun from panorama finds the brightest point of the sky and points the sun there for shadows. There are also exposure and haze (distant objects blend into the air).

Saving and publishing

  • A draft is saved automatically in this browser for each panorama, together with the model files.
  • To make the scene visible to everyone: ⇩ Package .zip, then unzip it into the site root. The archive already has the right paths: panoramas/…/name.scene.json and models/….
  • ⇩ .scene.json: the scene description only (the models must already be in models/).
  • ⇧ Import: a .scene.json file or a .zip package. ↺ Server version: discard local changes.

Preparing models

For phones keep the total complexity under 1–2 million triangles and textures at 4K or less. Export photogrammetry (Polycam, RealityScan, Metashape, Meshroom) as GLB or OBJ in metres. One command shrinks and compresses a model (needs Node.js):

npx @gltf-transform/cli optimize model.glb model-web.glb --compress draco --texture-compress webp --texture-size 4096

VR headset

Headset (or V) makes a link and a QR code that open the current image on a headset, with your 3D objects and these settings: the view (6DoF: walk inside the depth mesh; Stereo: the original stereo pair, head rotation only; Flat: a sphere), quality, scale and whether objects are shown. Open the link in the Meta Quest Browser (or any WebXR browser) and press Enter VR.

  • On a nomono3d server (the Colab notebook, for example) a local image, models added from disk and the scene are saved to the library first, so the headset gets exactly what you set up.
  • On a static site the link opens a library item with its published scene; objects that exist only in your browser are not included (export the scene package and add it to the library).
  • With the Colab notebook the links are Colab links: they open on any device signed in to the same Google account. In the Quest Browser sign in to google.com once. A public link (Cloudflare and others) is optional, for devices without your account. localhost addresses do not work on a headset.
  • On a device that can enter VR itself, Enter VR on this device starts at once.

Inside VR one compact menu (Y or B on the controllers, or the ☰ on the left wrist with hand tracking) switches the view mode, scale, quality, objects and items. Controllers and hands point and grab objects.

Tips for the best result

  • Shoot panoramas from a tripod at eye height: the automatic ground scale is then most accurate.
  • Parallax is only as good as the depth map's edges. Feel free to retouch a map in an image editor: whiter = nearer.
  • Photos with a clear foreground (a trunk, a person, a fence) and some distance behind it give the strongest effect. Keep Move moderate: large moves reveal more invented background.
  • Put objects on the ground (↓ to ground), turn on a shadow and “☀ Sun from panorama”: that is how they blend in best.
  • For an exhibition: ?kiosk in the address, a full-screen browser, images up to 8K.
